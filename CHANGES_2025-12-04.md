# Changes - December 4, 2025

## Standard vs Opt-in Feature Architecture

We have implemented a new architecture to separate "Standard" features (configurable core behavior) from "Opt-in" features (add-on modules). This allows for a more flexible and scalable multi-tenant system where businesses can customize their experience.

### Backend Changes

- **Module Registry (`Backend/app/core/modules.py`)**:
    - Created a central registry defining all available system modules (e.g., `loyalty`, `orders`, `billing`, `inventory`).
    - Defined vertical-specific defaults (`VERTICAL_EXTRA_MODULES`) to automatically enable relevant modules for different business types (e.g., Car Wash, Dispensary).

- **Dynamic Feature Calculation (`Backend/app/plugins/tenants/routes.py`)**:
    - Updated the tenant API to calculate active features dynamically.
    - **Logic**: `Active Features = Plan Modules + Vertical Extras + Tenant Overrides`.
    - This ensures that a tenant's features are a composition of their subscription plan, their industry vertical, and any specific add-ons they have enabled.

- **Context Awareness (`Backend/app/core/tenant_context.py`)**:
    - Updated the tenant context to expose these calculated features globally to the application, allowing for feature gating at the API level.

### Frontend Changes

- **Dynamic Configuration (`Frontend/src/config/TenantConfigProvider.tsx`)**:
    - Updated the provider to consume the new `features` map from the backend API.
    - Mapped backend feature keys to frontend `moduleFlags`, replacing the previous static/localStorage-based feature toggling.
    - This makes the frontend truly data-driven based on the tenant's actual configuration.

- **Marketplace UI (`Frontend/src/pages/admin/Marketplace.tsx`)**:
    - Created a new "Marketplace" page for admins.
    - Allows admins to browse available modules and toggle them on/off.
    - Toggling a module creates a "Tenant Override" on the backend, persisting the choice.

- **Loyalty Program Settings (`Frontend/src/pages/admin/LoyaltyProgramSettings.tsx`)**:
    - Created a new configuration page for the core Loyalty feature.
    - Allows businesses to choose between different loyalty logic types (e.g., "Points Based" vs "Stamps Based").
    - This setting is persisted to the tenant's configuration.

- **Navigation Updates (`Frontend/src/features/admin/nav/adminNavConfig.ts`)**:
    - Updated the admin sidebar navigation to respect the new dynamic feature flags.
    - Menu items now automatically hide if the corresponding module is not enabled for the tenant.

### Verification

- **Marketplace**: Visit `/admin/modules` to see available modules and toggle them.
- **Loyalty Settings**: Visit `/admin/loyalty-settings` to configure the loyalty program type.
- **Feature Gating**: Disable a module (e.g., "Orders") in the Marketplace and verify it disappears from the sidebar.
