# Change Summary — 2025-11-10

This change set standardizes all user-facing toast notifications, introduces a lightweight i18n layer for messages, adds a user preference toggle for notifications, and ensures frontend quality gates (lint, tests, build) remain green.

## Notification System Consolidation

- Replaced scattered `react-toastify` direct usages across pages (auth flows, admin pages, staff dashboards, subscription management, analytics, manual visit logging, car wash dashboard) with centralized helpers in `src/utils/notifications.ts`.
- Added key-based helper variants (`notifySuccessKey`, `notifyErrorKey`, `notifyInfoKey`, `notifyWarningKey`) integrating a minimal translator.
- Implemented deduplication (2.5s interval) to suppress rapid duplicate messages while allowing override via `skipDedupe`.
- Preserved analytics tracking for every toast (`track('toast', { level, message })`).

## Internationalization (i18n) Scaffold

- Created `src/utils/i18n.ts` with an English dictionary and `translate(key, params)` function.
- Added extensive notification keys covering: plans, modules, trials, subscriptions, portal, onboarding/OTP, user/staff management, analytics refresh, visits, wash lifecycle, session expiration, and notification preference.
- Introduced placeholder syntax `:{name}` (e.g. `Trial started for :{days} days`) with runtime replacement via params.

## User Preference (Silent Mode)

- Added `setNotificationsEnabled` / `getNotificationsEnabled` persisted to `localStorage`.
- Integrated a toggle UI in `Account.tsx` allowing users to enable/disable toast rendering while still recording analytics events.

## Documentation Enhancements

- Updated `Frontend/docs/notifications.md` to include: usage patterns, dedupe behavior, preference toggle example, and a comprehensive i18n key reference table.
- Clarified placeholder usage and guidance for adding future keys.

## Codebase Migrations (Representative Files Updated)

- Auth: `ForgotPassword.tsx`, `ResetPassword.tsx`, `OTPVerify.tsx`
- Admin: `SubscriptionPlansPage.tsx`, `SubscriptionManagePageNew.tsx`, `UsersList.tsx`, `StaffRegisterForm.tsx`, `ModulesAdmin.tsx`
- Staff: `ManualVisitLogger.tsx`, `CarWashDashboard.tsx`, `CustomerAnalytics.tsx`
- Shared: `api/api.ts` global 401 handler now uses key-based notification.
- Utilities: `notifications.ts`, `i18n.ts`, docs.

## Quality Gate Results (Post-Migration)

- ESLint: PASS (resolved all unused variable warnings after migration).
- TypeScript build (`npm run build`): PASS (no compile errors; production bundle generated successfully).
- Tests (Vitest): PASS — 54 tests passing, 1 skipped (unchanged social login skip). No new test failures introduced by migrations.

## Design & UX Consistency

- All toast styling centralized; removal of ad-hoc `toast.*` calls prevents inconsistent autoClose/position usage.
- Added guard against notification spam via dedupe, improving perceived stability.
- Preference toggle improves accessibility/usability for users sensitive to transient popups.

## Risk & Rollback Considerations

- Changes are additive/refactor; previous direct toast paths removed. Rollback would involve reverting the updated pages to use `toast.*` directly and deleting new i18n keys.
- No backend contract changes; all modifications are frontend-only and do not affect API surface.

## Summary

Centralized notifications now provide consistent, translatable, and user-controllable feedback across the application. All quality gates remain green, and documentation reflects the new patterns for future contributors.
